## Обзор

antimage — это готовая к продуктивному использованию плоскость управления для администрирования парка VPN и прокси-узлов из единой веб-панели. Построенная на согласовании желаемого состояния, она обеспечивает многопользовательское администрирование, всеобъемлющее журналирование аудита, протокольные адаптеры для Xray, WireGuard, Hysteria2, L2TP/IPsec и sing-box, с учётом трафика, принудительным применением квот и доставкой подписок.

**Ключевое отличие**: узлы подключаются к панели по mTLS — входящие порты не требуются. Расхождение конфигурации обнаруживается, а не молча перезаписывается. Отключившиеся узлы самовосстанавливаются по возвращении.

### Что вы получаете

- **Плоскость управления**: многопользовательский веб-UI с RBAC, 2FA по TOTP, журналом аудита и обновлениями в реальном времени через SSE
- **Агент узла**: автономный агент согласования с архитектурой протокольных адаптеров
- **Поддержка протоколов**: Xray (VLESS/VMess/Trojan), WireGuard, Hysteria2, L2TP/IPsec, sing-box
- **Управление трафиком**: учёт в реальном времени, принудительное применение квот, ограничения соединений
- **Система подписок**: генерация подписок V2Ray/Clash с кодированием base64
- **Оркестрация развёртывания**: канареечное и последовательное развёртывание с автоматическим откатом
- **Безопасность**: хэширование паролей Argon2id, частный УЦ с mTLS, отзыв сессий, защита от обхода каталогов
- **Наблюдаемость**: структурированное логирование, проверки работоспособности, метрики, история развёртываний

## Архитектура

antimage использует модель **согласования желаемого состояния**. Панель публикует, как узел *должен* выглядеть; агент сам решает, как этого достичь, и сообщает, что он сделал.

```
┌─────────────────────────────────────┐
│  Оператор (Браузер/CLI)             │
└──────────────┬──────────────────────┘
               │ HTTPS (API + Веб-UI)
┌──────────────▼──────────────────────┐
│  antimage-panel (Плоскость управл.) │
│  ├─ HTTP API + встроенный SPA :8080 │
│  ├─ gRPC плоскость управл.    :8443 │ (mTLS)
│  ├─ База данных SQLite (WAL)        │
│  ├─ Частный УЦ                      │
│  └─ Оркестратор развёртывания       │
└──────────────┬──────────────────────┘
               │ Агент подключается (mTLS)
               │ Входящий порт не нужен
┌──────────────▼──────────────────────┐
│  antimage-node (Агент)              │
│  ├─ Регистрация (одноразовый токен) │
│  ├─ Поток управления (mTLS)         │
│  ├─ Слой адаптеров                  │
│  │   ├─ Xray                        │
│  │   ├─ WireGuard                   │
│  │   ├─ Hysteria2                   │
│  │   ├─ L2TP/IPsec                  │
│  │   └─ sing-box                    │
│  └─ Слой принудительного применения │
│      ├─ Проверка квот               │
│      ├─ Ограничения соединений      │
│      └─ Учёт трафика                │
└─────────────────────────────────────┘
```

### Основные концепции

**Желаемое состояние**: каждая конфигурация узла канонизируется (RFC 8785 JCS), хэшируется алгоритмом SHA-256 и получает номер ревизии. Панель публикует желаемое состояние; агент применяет его.

**Наблюдаемое состояние**: агент сообщает, что он фактически применил, включая успех/неудачу каждого шага и обнаружение расхождения конфигурации.

**Цикл согласования**: агент опрашивает желаемое состояние, сравнивает с наблюдаемым состоянием, планирует изменения, применяет их и сообщает результаты. Расхождение обнаруживается, когда применённый хэш не совпадает с желаемым хэшом.

**Контракт адаптера**: каждый протокольный адаптер реализует `Observe() → Plan() → Apply() → Verify()`. Агент оркестрирует; адаптеры выполняют.

**Слой принудительного применения**: принудительное применение политик в реальном времени для квот, ограничений соединений и ограничений скорости (через tc в Linux).

## Возможности

### Плоскость управления

- **Многопользовательский RBAC**: четыре встроенные роли (`super_admin`, `admin`, `reseller`, `readonly`) с ограничением доступа по узлам
- **Аутентификация**: хэширование паролей Argon2id, 2FA по TOTP, одноразовые коды восстановления, ограничение частоты попыток входа, блокировка учётной записи
- **Сессии**: непрозрачные серверные сессии (не JWT) — отзыв действует немедленно
- **Журнал аудита**: работающий только на добавление журнал аудита, охватывающий привилегированные действия, отказы авторизации, отклонения при валидации
- **Реестр узлов**: регистрация на основе сертификатов с одноразовыми токенами и частным УЦ
- **Согласование желаемого состояния**: проверка хэша SHA-256, обнаружение расхождений, пошаговые отчёты о применении
- **Обновления в реальном времени**: Server-Sent Events (SSE) для статуса узлов в реальном времени
- **Веб-UI**: SPA на React с поддержкой письма справа налево, интернационализацией (английский, фарси, русский, китайский, арабский)
- **Оркестрация развёртывания**: канареечное и последовательное развёртывание с автоматическим откатом при сбое

### Агент узла

- **Никаких входящих портов**: агент подключается к панели по mTLS — дружелюбно к брандмауэру
- **Аутентификация mTLS**: взаимный TLS с частным УЦ, закрепление сертификата, отзыв через список разрешённых
- **Самовосстановление**: отключившиеся узлы автоматически согласуются по возвращении
- **Архитектура адаптеров**: подключаемые протокольные адаптеры с контрактом `Observe → Plan → Apply → Verify`
- **Горячая перезагрузка**: обновление конфигурации без перезапуска службы (зависит от протокола)
- **Начальная установка по SSH**: автоматическая установка агента по SSH с закреплением ключа хоста

### Протокольные адаптеры

- **Xray**: VLESS, VMess, Trojan с управлением пользователями в реальном времени, учётом трафика, отслеживанием соединений
- **WireGuard**: родной VPN уровня ядра с управлением пирами и статистикой трафика
- **Hysteria2**: протокол на основе QUIC с поддержкой UDP и родной конфигурацией пропускной способности
- **L2TP/IPsec**: strongSwan + xl2tpd с аутентификацией PSK и учётом через nftables
- **sing-box**: универсальная прокси-платформа с поддержкой нескольких протоколов

### Управление трафиком

- **Учёт в реальном времени**: отслеживание трафика на уровне байтов для каждого пользователя (исходящий/входящий)
- **Принудительное применение квот**: немедленный отказ при допуске при превышении квоты (задержка <1 мс)
- **Ограничения соединений**: отслеживание соединений для каждого пользователя с немедленным разрывом при нарушении
- **Ограничения скорости**: внешнее формирование пропускной способности на основе tc (Linux)
- **Немедленное отключение**: немедленный отзыв пользователя с разрывом активной сессии

### Подписки

- **Формат V2Ray**: закодированные в base64 ссылки vmess:// с автоматической генерацией конфигурации
- **Формат Clash**: конфигурация YAML с группами прокси и правилами
- **Несколько протоколов**: поддерживает Xray (VLESS/VMess/Trojan), WireGuard, Hysteria2
- **Динамические обновления**: подписки отражают текущее состояние пользователя и активные узлы
- **Отображение трафика**: показывает оставшуюся квоту и использование пропускной способности в подписке

## Требования

### Хост панели

- **ОС**: Linux x86-64 или ARM64 (Debian, Ubuntu или любой современный Linux)
- **Ресурсы**: ~200 МБ на диске для бинарного файла, базы данных, журнала аудита (растёт вместе с размером парка)
- **Зависимости**: нет — статически скомпилированный бинарный файл Go со встроенным SQLite
- **Порты**: TCP 8080 (HTTP), TCP 8443 (gRPC)

### Управляемый узел

- **ОС**: Debian 11/12/13 или Ubuntu 20.04/22.04/24.04 (x86-64 или ARM64)
- **Зависимости**: systemd, curl
- **Сеть**: исходящий TCP до порта gRPC панели (8443) — **входящий порт не требуется**
- **Разрешения**: root-доступ для управления службами и конфигурации сети

### Сборка из исходников

- **Go**: 1.26 или новее
- **Node.js**: 20+ и npm (для сборки веб-UI)
- **Make**: опционально (можно использовать прямой `go build`)

## Установка

### Продуктивная установка (рекомендуется)

**Для конечных пользователей npm/Node.js не требуется.**

#### 1. Скачать предсобранный бинарный файл

Скачайте последний выпуск для вашей платформы из [GitHub Releases](https://github.com/devprogrmer/antimage/releases):

```bash
# Linux x86-64
wget https://github.com/devprogrmer/antimage/releases/download/v1.0.0/antimage-panel-linux-amd64
wget https://github.com/devprogrmer/antimage/releases/download/v1.0.0/antimage-ctl-linux-amd64
wget https://github.com/devprogrmer/antimage/releases/download/v1.0.0/SHA256SUMS

# Проверить контрольные суммы
sha256sum -c SHA256SUMS --ignore-missing

# Сделать исполняемым
chmod +x antimage-panel-linux-amd64 antimage-ctl-linux-amd64
```

> **Примечание**: предсобранные бинарные файлы содержат встроенный веб-UI. Установка npm/Node.js не требуется.

#### 2. Установить в систему

```bash
sudo mv antimage-panel-linux-amd64 /usr/local/bin/antimage-panel
sudo mv antimage-ctl-linux-amd64 /usr/local/bin/antimage-ctl
```

#### 3. Запустить панель

```bash
sudo mkdir -p /var/lib/antimage && sudo chmod 700 /var/lib/antimage
sudo /usr/local/bin/antimage-panel \
  --data-dir /var/lib/antimage \
  --http :8080 \
  --grpc :8443 \
  --grpc-hosts panel.example.com
```

Панель выводит отпечаток УЦ, необходимый для регистрации узла:

```
level=INFO msg="antimage-panel listening" http=:8080 grpc=:8443 ca_fingerprint=sha256:ABC123...
```

> **Критично**: `--grpc-hosts` должен совпадать с DNS-именем, которое используют агенты для подключения.

#### 4. Создать первого администратора

```bash
sudo /usr/local/bin/antimage-ctl --data-dir /var/lib/antimage \
  create-admin admin 'your-strong-passphrase' super_admin
```

#### 5. Открыть веб-UI

Откройте `http://SERVER_IP:8080` и войдите с учётными данными из шага 4.

### Установка для разработки

**Только для участников разработки и разработчиков.**

#### 1. Клонировать репозиторий

```bash
git clone https://github.com/devprogrmer/antimage.git
cd antimage
```

#### 2. Собрать фронтенд

```bash
cd web && npm install && npm run build && cd ..
```

#### 3. Собрать бинарные файлы

```bash
CGO_ENABLED=0 go build -trimpath -o bin/antimage-panel ./cmd/antimage-panel
CGO_ENABLED=0 go build -trimpath -o bin/antimage-node  ./cmd/antimage-node
CGO_ENABLED=0 go build -trimpath -o bin/antimage-ctl   ./cmd/antimage-ctl
```

#### 4. Запустить панель для разработки

```bash
sudo mkdir -p /var/lib/antimage && sudo chmod 700 /var/lib/antimage
sudo ./bin/antimage-panel \
  --data-dir /var/lib/antimage \
  --http :8080 \
  --grpc :8443 \
  --grpc-hosts localhost
```

Для разработки фронтенда с горячей перезагрузкой:

```bash
# Терминал 1: запустить панель с dev-прокси
sudo ./bin/antimage-panel --dev-proxy http://localhost:5173 \
  --data-dir /var/lib/antimage --http :8080 --grpc :8443

# Терминал 2: запустить dev-сервер Vite
cd web && npm run dev
```

## Быстрый старт

### Добавление первого узла

#### Вариант 1: однострочная начальная установка (рекомендуется)

1. Создайте узел в веб-UI или с помощью CLI
2. Скопируйте токен регистрации
3. Выполните на целевом узле:

```bash
curl -fsSL https://panel.example.com/install.sh | sudo bash -s -- YOUR_ENROLMENT_TOKEN
```

Или с пользовательским URL панели:

```bash
PANEL_URL=https://panel.example.com curl -fsSL https://panel.example.com/install.sh | sudo bash -s -- YOUR_ENROLMENT_TOKEN
```

Установщик автоматически:
- Проверяет привилегии root и совместимость ОС (Linux x86-64/ARM64)
- Проверяет формат токена регистрации
- Скачивает бинарный файл агента с ограничениями по времени (5 минут)
- Проверяет контрольную сумму SHA-256 (отклоняет при несовпадении)
- Создаёт выделенного системного пользователя `antimage` (без оболочки входа)
- Устанавливает в `/opt/antimage/antimage-node` с безопасными разрешениями
- Создаёт усиленную службу systemd с:
  - Функциями безопасности: NoNewPrivileges, PrivateTmp, ProtectSystem=strict
  - Ограничением возможностей: только CAP_NET_ADMIN, CAP_NET_BIND_SERVICE
  - Автоматическим перезапуском при сбое (задержка 5 с)
- Регистрирует узел на панели с использованием mTLS
- Включает и запускает службу
- Проверяет, что служба запущена

**Замечания по безопасности:**
- Токены регистрации должны быть длиной 16+ буквенно-цифровых символов
- Проверка контрольной суммы предотвращает подмену бинарного файла
- Неудачная проверка запускает автоматическую очистку
- Служба работает от непривилегированного пользователя с минимальными возможностями

#### Вариант 2: ручная установка

```bash
# Установить бинарный файл
sudo install -m 0755 antimage-node /usr/local/bin/antimage-node

# Создать конфигурацию
sudo mkdir -p /etc/antimage /var/lib/antimage
sudo chmod 700 /var/lib/antimage
sudo tee /etc/antimage/node.yaml >/dev/null <<'YAML'
panel_url: https://panel.example.com:8443
token: YOUR_ENROLMENT_TOKEN
ca_fingerprint: sha256:ABC123...
state_dir: /var/lib/antimage
YAML
sudo chmod 600 /etc/antimage/node.yaml

# Установить и запустить службу
sudo cp packaging/antimage-node.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now antimage-node
```

#### Вариант 3: начальная установка по SSH из панели

Используйте `POST /api/v1/nodes/{nodeID}/bootstrap-ssh` с учётными данными SSH. Панель подключается по SSH и автоматически запускает установщик.

## Конфигурация

### Конфигурация панели

Панель принимает конфигурацию через флаги CLI или переменные окружения:

```bash
antimage-panel [ОПЦИИ]

Опции:
  --data-dir PATH          Каталог базы данных и состояния (по умолчанию: ./data)
  --http ADDR              Адрес прослушивания HTTP (по умолчанию: :8080)
  --grpc ADDR              Адрес прослушивания gRPC (по умолчанию: :8443)
  --grpc-hosts HOSTS       DNS-имена через запятую для TLS-сертификата gRPC (обязательно)
  --log-level LEVEL        Уровень логирования: debug, info, warn, error (по умолчанию: info)
  --log-format FORMAT      Формат логов: json, text (по умолчанию: text)
```

Переменные окружения используют префикс `ANTIMAGE_`:

```bash
ANTIMAGE_DATA_DIR=/var/lib/antimage
ANTIMAGE_HTTP=:8080
ANTIMAGE_GRPC=:8443
ANTIMAGE_GRPC_HOSTS=panel.example.com
ANTIMAGE_LOG_LEVEL=info
```

### Конфигурация узла

Агент читает из `/etc/antimage/node.yaml`:

```yaml
panel_url: https://panel.example.com:8443
token: "enrolment-token-from-panel"
ca_fingerprint: "sha256:fingerprint-from-panel"
state_dir: /var/lib/antimage
log_level: info
```

### TLS и mTLS

- **HTTP панели**: использует системный TLS или обратный прокси (Nginx, Caddy)
- **gRPC панели**: автоматически генерирует сертификат mTLS, подписанный частным УЦ
- **Агент**: проверяет сертификат панели по `ca_fingerprint`, затем предъявляет клиентский сертификат
- **Регистрация**: обмен одноразовым токеном, затем аутентификация на основе сертификата

## Управление пользователями

### Создание пользователей (субъектов)

Пользователи называются «субъектами» в API. Создание через веб-UI или CLI:

```bash
# Через CLI
antimage-ctl --data-dir /var/lib/antimage create-subject \
  --username user123 \
  --password "user-password" \
  --protocol xray
```

### Политики субъектов

Субъекты могут иметь политики для:

- **Квоты**: общее количество разрешённых байтов (исходящий + входящий)
- **Ограничения соединений**: максимальное количество одновременных соединений (только Xray)
- **Ограничения скорости**: ограничения скорости загрузки/скачивания (требуется tc на узлах)
- **Истечение срока**: дата истечения срока действия учётной записи

Политики применяются в реальном времени слоем принудительного применения.

### Многопользовательский режим

Используйте роль `reseller` для ограничения администраторов определёнными узлами. Каждый реселлер видит только назначенные ему узлы и субъекты.

## Управление узлами

### Жизненный цикл узла

1. **Создание**: регистрация узла на панели, генерация токена регистрации
2. **Регистрация**: агент подключается с токеном, получает клиентский сертификат
3. **Согласование**: агент подписывается на поток желаемого состояния, применяет конфигурацию
4. **Мониторинг**: панель отслеживает работоспособность узла, сходимость ревизий, обнаружение расхождений
5. **Отзыв**: удаление узла с панели, сертификат немедленно блокируется

### Работоспособность узла

Панель отслеживает:

- **Последнее появление**: временная метка последнего heartbeat gRPC
- **Статус**: `online`, `offline`, `maintenance`, `error`
- **Ревизии**: `desired_revision` против `applied_revision`
- **Расхождение**: несовпадение SHA-256 между желаемым и применённым состоянием
- **Версия агента**: сообщает версию программного обеспечения агента

### Службы

Каждый узел может одновременно запускать несколько протокольных адаптеров:

```json
{
  "services": [
    {"adapter_kind": "xray", "params": {...}},
    {"adapter_kind": "wireguard", "params": {...}},
    {"adapter_kind": "hysteria2", "params": {...}}
  ]
}
```

## Учёт трафика и квоты

### Учёт в реальном времени

Адаптер Xray опрашивает Stats API каждые 5-10 секунд:

```go
// Поток Агент -> Панель gRPC
{
  "subject_id": 123,
  "uplink_bytes": 1048576,
  "downlink_bytes": 2097152,
  "timestamp": "2026-08-23T00:00:00Z"
}
```

### Принудительное применение квот

- **Проверка допуска**: перед разрешением соединения Enforcer проверяет текущее использование против квоты
- **Немедленный отказ**: если квота превышена, соединение отклоняется менее чем за 1 мс
- **Ретроактивная очистка**: фоновая задача разрывает активные сессии при исчерпании квоты
- **Льготный период**: настраиваемое льготное окно перед жёстким отсечением

### Ограничения соединений

Xray отслеживает активные соединения для каждого субъекта. При достижении ограничения:

```
INFO terminating connection due to policy violation subject_id=1 reason="connection limit reached (2/2)"
```

## Стратегии развёртывания

### Канареечное развёртывание

Сначала развёртывание на подмножестве узлов, мониторинг ошибок, затем продолжение:

```bash
POST /api/v1/deployments
{
  "strategy": "canary",
  "canary_percent": 10,
  "max_failures": 1
}
```

### Последовательное развёртывание

Последовательное обновление узлов с настраиваемым размером пакета:

```bash
POST /api/v1/deployments
{
  "strategy": "rolling",
  "batch_size": 5,
  "batch_interval_seconds": 30
}
```

### Всё сразу

Немедленное обновление всех узлов:

```bash
POST /api/v1/deployments
{
  "strategy": "all_at_once"
}
```

### Автоматический откат

Если узлу не удаётся применить в течение времени ожидания или он сообщает о сбое сходимости, развёртывание автоматически откатывается:

```
WARN deployment failed node=edge-02 reason="apply timeout (120s)"
INFO rolling back deployment deployment_id=42
```

## Модель безопасности

### Аутентификация и авторизация

- **Хэширование паролей**: Argon2id с memory=64MB, time=3, parallelism=4
- **2FA по TOTP**: соответствует RFC 6238, окно 30 секунд, одноразовые коды
- **Коды восстановления**: 10 одноразовых кодов, генерируемых при регистрации TOTP
- **Сессии**: непрозрачные токены, хранимые на стороне сервера, немедленный отзыв при выходе/удалении
- **Ограничение частоты**: 5 неудачных попыток входа → блокировка учётной записи на 15 минут
- **RBAC**: четыре роли с иерархическими разрешениями, принудительное применение области на уровне SQL

### Сетевая безопасность

- **mTLS**: взаимный TLS между панелью и агентами с частным УЦ
- **Закрепление сертификата**: агенты проверяют сертификат панели по закреплённому отпечатку
- **Отзыв через список разрешённых**: сертификаты удалённых узлов немедленно отклоняются
- **Никаких входящих портов**: агенты подключаются наружу — дружелюбно к брандмауэру

### Защита данных

- **Шифрование базы данных**: секреты зашифрованы с помощью мастер-ключа (через `internal/shared/secrets`)
- **Неизменяемость аудита**: работающий только на добавление журнал аудита, удаления не разрешены
- **Защита от обхода каталогов**: файловые операции ограничены разрешёнными каталогами
- **Защита от символических ссылок**: предотвращает атаки с символическими ссылками на файлы конфигурации/состояния

### Ограничения

- **HTTP панели в виде открытого текста**: используйте обратный прокси (Nginx/Caddy) с TLS
- **Нет WAF**: базовое ограничение частоты, рассмотрите внешний WAF для продуктивного использования
- **Нет защиты от CSRF**: используйте куки SameSite=Lax (по умолчанию)
- **Нет политики безопасности контента**: добавьте через заголовки обратного прокси

## Известные ограничения

### Специфичные для протокола

| Протокол | Ограничение | Обходной путь |
|----------|-------------|---------------|
| **Xray** | поля upSpeed/downSpeed игнорируются временем выполнения | Используйте внешний `tc` (traffic control) в Linux |
| **Xray** | отслеживание соединений имеет задержку опроса 5-10 с | принудительное применение по мере возможности, не мгновенно |
| **WireGuard** | нет встроенной интеграции учёта трафика | требуется ручной опрос `wg show transfer` |
| **Hysteria2** | проверка времени выполнения не выполнена | конфигурация сгенерирована, фактическое принудительное применение НЕ ПРОВЕРЕНО |
| **L2TP/IPsec** | нет встроенных ограничений соединений | требуется внешнее принудительное применение |
| **sing-box** | нет горячей перезагрузки, требуется полный перезапуск | разрушительно для обновлений пользователей |

### Специфичные для платформы

- **Ограничения скорости**: требуют Linux `tc` (traffic control) с `CAP_NET_ADMIN`
- **Ограничения скачивания**: требуют `tc` + устройство IFB (Intermediate Functional Block)
- **Windows**: только разработка, не готово к продуктивному использованию
- **macOS**: только хост сборки, не цель развёртывания

### Масштаб и производительность

- **Единственная панель**: нет горизонтального масштабирования, только вертикальное
- **SQLite**: ограничение на одного записывающего, подходит для <10 000 пользователей на панель
- **Скорость развёртывания**: последовательные обновления узлов, 30+ с для больших парков
- **Производительность в больших масштабах**: НЕ ПРОВЕРЕНО за пределами тестовых рабочих нагрузок

### ✅ Готовые к продуктивному использованию компоненты

1. **Начните с малого**: разверните только с Xray для первого продуктивного запуска

5. **Брандмауэр**: ограничьте доступ к панели IP-адресами операторов
6. **Секреты**: защитите `/var/lib/antimage` (содержит мастер-ключ и УЦ)

## Инструкции по обновлению

### С v0.1.0 до v1.0.0

Это мажорный выпуск с критическими изменениями.

#### Контрольный список перед обновлением

1. **Резервная копия базы данных**:
   ```bash
   sudo antimage-ctl --data-dir /var/lib/antimage backup /backup/antimage-$(date +%Y%m%d).db
   ```

2. **Остановить службы**:
   ```bash
   sudo systemctl stop antimage-panel
   sudo systemctl stop antimage-node  # На всех узлах
   ```

3. **Резервная копия конфигурации**:
   ```bash
   sudo cp -r /var/lib/antimage /backup/antimage-data-$(date +%Y%m%d)
   sudo cp /etc/antimage/node.yaml /backup/  # На узлах
   ```

#### Шаги обновления

1. **Заменить бинарные файлы**:
   ```bash
   sudo cp bin/antimage-panel /usr/local/bin/
   sudo cp bin/antimage-node /usr/local/bin/  # На узлах
   sudo cp bin/antimage-ctl /usr/local/bin/
   ```

2. **Запустить миграции** (автоматически при первом запуске):
   ```bash
   sudo systemctl start antimage-panel
   # Проверить логи: journalctl -u antimage-panel -f
   ```

3. **Проверить работоспособность панели**:
   ```bash
   curl http://localhost:8080/health
   # Ожидается: {"status":"healthy"}
   ```

4. **Перезапустить узлы**:
   ```bash
   sudo systemctl start antimage-node
   ```

5. **Проверить согласование**:
   - Проверьте веб-UI: все узлы показывают `applied_revision == desired_revision`
   - Проверьте расхождения: нет несовпадений хэшей

#### Критические изменения

- **Схема базы данных**: миграция 00022 добавляет статус `maintenance` в таблицу узлов
- **Изменения API**: эндпоинты развёртывания теперь требуют явных проверок RBAC
- **Конфигурация**: изменения конфигурации не требуются

#### Процедура отката

Если обновление не удаётся:

1. **Остановить службы**:
   ```bash
   sudo systemctl stop antimage-panel antimage-node
   ```

2. **Восстановить бинарные файлы**:
   ```bash
   sudo cp /backup/antimage-panel-v0.1.0 /usr/local/bin/antimage-panel
   sudo cp /backup/antimage-node-v0.1.0 /usr/local/bin/antimage-node
   ```

3. **Восстановить базу данных**:
   ```bash
   sudo cp /backup/antimage-YYYYMMDD.db /var/lib/antimage/antimage.db
   ```

4. **Перезапустить службы**:
   ```bash
   sudo systemctl start antimage-panel antimage-node
   ```

### Миграция с других панелей

antimage в настоящее время не поддерживает миграцию с Marzban, 3x-ui или других панелей. Вы должны:

1. Экспортировать учётные данные пользователей из старой панели
2. Создать пользователей вручную в antimage через API/CLI
3. Распространить новые ссылки на подписки

### Области, требующие помощи

- **CI/CD**: рабочие процессы GitHub Actions
- **Тесты времени выполнения Hysteria2**: требуется среда тестирования Linux
- **Интеграция WireGuard**: интеграция учёта с Enforcer
- **Интеграция L2TP**: интеграция учёта nftables
- **Тесты производительности**: крупномасштабное тестирование (10k+ пользователей)
- **Документация**: архитектурные диаграммы, видеоуроки
- **Интернационализация**: переводы на дополнительные языки
