# antimage

**Languages:** [English](README.md) · **فارسی** · [Русский](README.ru.md) · [简体中文](README.zh-CN.md) · [العربية](README.ar.md)

<div dir="rtl" align="right">

لایهٔ کنترل خودمیزبان برای مدیریت ناوگانی از گره‌های VPN/پروکسی از یک پنل
واحد: نقش‌های چندادمینی، دسترسی دامنه‌بندی‌شده، ردّ ممیزی فقط-افزودنی، و
تطبیق وضعیت مطلوب روی gRPC با احراز هویت دوطرفه.

> **وضعیت: SP1 — ستون فقرات لایهٔ کنترل.** این نسخه پایه را فراهم می‌کند:
> احراز هویت، کنترل دسترسی، ممیزی، رجیستری گره‌ها، ثبت‌نام با mTLS،
> بوت‌استرپ، قرارداد آداپتور، سلامت، و پوستهٔ UI. تنها آداپتوری که عرضه
> می‌شود یک **stub** است که برای اثبات هم‌گرایی به‌صورت سرتاسری به کار
> می‌رود. آداپتورهای واقعی پروتکل، مدیریت مشترکان، حسابداری ترافیک و سهمیه‌ها
> صراحتاً خارج از دامنهٔ SP1 هستند — به
> [محدودیت‌های شناخته‌شده](#محدودیتهای-شناختهشده) نگاه کنید.

## antimage چیست

antimage از دو برنامه و یک CLI تشکیل شده است:

- **`antimage-panel`** — لایهٔ کنترل. API اپراتور و رابط وب را روی HTTP عرضه
  می‌کند، و یک لایهٔ کنترل gRPC که عامل‌ها روی mTLS به آن وصل می‌شوند.
- **`antimage-node`** — عامل. روی هر سرور تحت مدیریت اجرا می‌شود، خودش را
  ثبت‌نام می‌کند، سپس یک جریان بلندعمر به پنل نگه می‌دارد و میزبان را به سمت
  وضعیت مطلوبی که پنل منتشر می‌کند تطبیق می‌دهد.
- **`antimage-ctl`** — مدیریت و بازیابی محلی، که مستقیماً با پایگاه‌دادهٔ پنل
  کار می‌کند. این راه بازگشت به درون است وقتی رابط کاربری در دسترس نیست یا
  همهٔ ادمین‌ها بیرون قفل شده‌اند.

انتخاب طراحی محوری، **تطبیق وضعیت مطلوب روی جریانی که عامل آغاز می‌کند** است،
نه RPC دستوری. پنل منتشر می‌کند که یک گره *چگونه باید* باشد؛ عامل خودش تصمیم
می‌گیرد چگونه به آنجا برسد و گزارش می‌دهد چه کرده است. یعنی گره‌ها به هیچ پورت
ورودی نیاز ندارند، گرهٔ آفلاین هنگام بازگشت خودش را ترمیم می‌کند، و انحراف
پیکربندی تشخیص داده می‌شود، نه اینکه بی‌صدا بازنویسی شود.

## معماری

```
                    ┌──────────────────────────────┐
   operator ──HTTP──►  antimage-panel              │
   (browser/CLI)     │  ├─ HTTP API + embedded SPA │  :8080
                     │  ├─ gRPC control plane      │  :8443  (mTLS)
                     │  ├─ SQLite (WAL)            │
                     │  └─ private CA              │
                     └───────────▲──────────────────┘
                                 │ agent dials out; no inbound port on the node
                     ┌───────────┴──────────────────┐
                     │  antimage-node (agent)       │
                     │  ├─ enrol (one-time token)   │
                     │  ├─ control stream (mTLS)    │
                     │  └─ adapter: observe → plan  │
                     │              → apply → verify│
                     └──────────────────────────────┘
```

**بازنگری‌ها.** هر تغییر در وضعیت مطلوب یک گره از یک گلوگاه واحد عبور می‌کند
که سند را متعارف‌سازی می‌کند (RFC 8785 JCS)، آن را با SHA-256 هش می‌کند و
`desired_revision` را دقیقاً یک واحد بالا می‌برد. `applied_revision` تنها
زمانی جلو می‌رود که عامل هم‌گرایی را گزارش کند **و** هشی که اعمال کرده با هشی
که پنل ثبت کرده یکی باشد. برابری شمارهٔ بازنگری همراه با ناهمخوانی هش، یک خطای
یکپارچگی است، نه هم‌گرایی.

**کنترل دسترسی دولایه.** هر درخواست از یک دروازهٔ صریح مجوز `rbac.Check` عبور
می‌کند، و هر پرس‌وجوی دامنه‌بندی‌شده به‌طور مستقل یک محمول (predicate) دامنه در
SQL اعمال می‌کند. فراموش‌کردن هر کدام از این دو به‌تنهایی دیده می‌شود، چون هر
کدام جداگانه تست می‌شوند.

## ویژگی‌ها

- چند ادمین با چهار نقش داخلی: `super_admin`، `admin`، `reseller`، `readonly`
- دامنه‌بندی دسترسی به ازای هر گره، که در SQL اعمال می‌شود نه فقط در هندلرها
- لاگ ممیزی فقط-افزودنی که کنش‌های ممتاز، ردهای کنترل دسترسی و ردهای اعتبارسنجی
  را پوشش می‌دهد
- نشست‌های مبهم سمت سرور (نه JWT)، بنابراین ابطال بی‌درنگ اثر می‌کند
- احراز هویت دوعاملی TOTP با کدهای بازیابی یک‌بارمصرف
- محدودسازی نرخ ورود و قفل‌شدن حساب
- ثبت‌نام گره با توکن یک‌بارمصرف و یک CA خصوصی
- ابطال از راه فهرست مجاز: حذف یک گره بی‌درنگ گواهی‌اش را بیرون قفل می‌کند
- تطبیق وضعیت مطلوب با تشخیص انحراف و گزارش اعمال گام‌به‌گام
- وضعیت زندهٔ گره‌ها روی Server-Sent Events
- بوت‌استرپ SSH با پین‌کردن کلید میزبان، بدون هرگز ماندگارکردن اعتبارنامه‌ها
- رابط وب با پشتیبانی الزام‌شده از راست‌به‌چپ و بین‌المللی‌سازی
- مدیریت مشترکان با سهمیهٔ ترافیک، انقضا، انجماد و دستگاه‌ها؛ نوار مصرف و
  روزهای باقی‌مانده در فهرست کاربران
- لینک اشتراک V2Ray/Clash/sing-box با هدر استاندارد `Subscription-Userinfo`
  برای نمایش مصرف و انقضا داخل کلاینت‌ها
- صفحهٔ اطلاعات اشتراک برای مرورگر: خودکفا، پنج‌زبانه (فارسی و عربی راست‌به‌چپ)،
  با حلقهٔ مصرف، روزهای باقی‌مانده، دکمهٔ کپی لینک در همهٔ قالب‌ها، کد QR و
  معرفی برنامه‌های کلاینت — به‌جای دیوار base64

## پیش‌نیازها

**میزبان پنل**
- Linux x86-64 یا ARM64
- حدود ۲۰۰ مگابایت دیسک برای باینری، پایگاه‌داده و لاگ ممیزی؛ با اندازهٔ ناوگان
  رشد می‌کند
- بدون پایگاه‌دادهٔ بیرونی، بروکر پیام یا کش — فقط SQLite

**گره تحت مدیریت**
- Debian 11/12/13 یا Ubuntu 20.04/22.04/24.04، x86-64 یا ARM64
- `systemd`، `curl`
- TCP خروجی به پورت gRPC پنل. **هیچ پورت ورودی‌ای لازم نیست.**

**ساخت از سورس**
- Go 1.26 یا جدیدتر
- Node.js 20+ و npm (فقط برای ساخت رابط وب)

## سیستم‌عامل‌های پشتیبانی‌شده

| مؤلفه | پشتیبانی‌شده | راستی‌آزمایی |
|---|---|---|
| `antimage-node` | Debian 11/12/13, Ubuntu 20.04/22.04/24.04 (amd64, arm64) | `install.sh` بنا بر طراحی هر چیز دیگری را رد می‌کند |
| `antimage-panel` | هر Linux با همان معماری‌ها | کراس‌کامپایل و تست‌شده در CI |
| میزبان ساخت | Linux, macOS, Windows | مجموعهٔ تست روی هر سه اجرا می‌شود |

`install.sh` عمداً از کار با توزیع‌های پشتیبانی‌نشده **سر باز می‌زند**، به‌جای
اینکه نام بسته‌ها را حدس بزند.

## نصب

### کلون و ساخت

```bash
git clone https://github.com/devprogrmer/antimage.git
cd antimage
```

نخست رابط وب را بسازید — پنل آن را در خود جاسازی می‌کند:

```bash
cd web && npm ci && npm run build && cd ..
```

سپس باینری‌ها:

```bash
make build
```

یا بدون `make`:

```bash
CGO_ENABLED=0 go build -trimpath -o bin/antimage-panel ./cmd/antimage-panel
CGO_ENABLED=0 go build -trimpath -o bin/antimage-node  ./cmd/antimage-node
CGO_ENABLED=0 go build -trimpath -o bin/antimage-ctl   ./cmd/antimage-ctl
```

`CGO_ENABLED=0` عمدی است: درایور SQLite با Go خالص نوشته شده، پس باینری‌ها
ایستا هستند و روی ماشین مقصد به libc نیاز ندارند.

### راه‌اندازی پنل

```bash
sudo mkdir -p /var/lib/antimage && sudo chmod 700 /var/lib/antimage
sudo ./bin/antimage-panel \
  --data-dir /var/lib/antimage \
  --http :8080 \
  --grpc :8443 \
  --grpc-hosts panel.example.com
```

در نخستین اجرا، پنل کلید اصلی، CA خصوصی و پایگاه‌دادهٔ خود را تولید می‌کند و
اثر انگشت CA را چاپ می‌کند که آن را روی گره‌ها پین خواهید کرد:

```
level=INFO msg="antimage-panel listening" http=:8080 grpc=:8443 ca_fingerprint=… grpc_cert_hosts=[panel.example.com]
```

> **`--grpc-hosts` باید نام‌هایی را فهرست کند که عامل‌ها واقعاً به آن‌ها وصل
> می‌شوند.** این نام‌ها به SANهای گواهی TLS پنل تبدیل می‌شوند. یک ناهمخوانی،
> دست‌دهی همهٔ گره‌ها را یکجا از کار می‌اندازد و تا وقتی عاملی تلاش نکند نامرئی
> می‌ماند.

### ساخت نخستین ادمین

```bash
sudo ./bin/antimage-ctl --data-dir /var/lib/antimage \
  create-admin admin 'a-long-passphrase' super_admin
```

سپس `http://localhost:8080` را باز کنید و وارد شوید.

### نصب پنل به‌عنوان سرویس

```bash
sudo cp bin/antimage-panel /usr/local/bin/
sudo useradd --system --home /var/lib/antimage --shell /usr/sbin/nologin antimage
sudo chown -R antimage:antimage /var/lib/antimage
sudo cp packaging/antimage-panel.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now antimage-panel
```

این یونیت با `User=antimage` و همراه با `NoNewPrivileges`،
`ProtectSystem=strict`، `ProtectHome` و `PrivateTmp` اجرا می‌شود. **شما باید
آن کاربر را بسازید** — بسته‌بندی این کار را برایتان انجام نمی‌دهد.

## افزودن گره

### تک‌خطی بوت‌استرپ

گره را در رابط کاربری (یا با `antimage-ctl`) بسازید، توکن ثبت‌نام را بردارید و
این را **روی خود گره** اجرا کنید:

```bash
curl -fsSL https://panel.example.com/install.sh | sudo bash -s -- \
  --panel https://panel.example.com \
  --token YOUR_ENROLMENT_TOKEN \
  --ca-fingerprint THE_PANEL_CA_FINGERPRINT
```

`install.sh` سیستم‌عامل و معماری را بررسی می‌کند، عامل و SHA-256 آن را دانلود
می‌کند، **پیش از نصب چک‌سام را راستی‌آزمایی می‌کند**،
`/etc/antimage/node.yaml` را با مود 0600 می‌نویسد، یک یونیت systemd نصب می‌کند
و آن را راه می‌اندازد. اجرای دوباره، نصب را در جا ارتقا می‌دهد بدون آنکه توکن
تازه‌ای مصرف کند.

دادن `--ca-fingerprint` از یک کانال خارج از باند، مسیر مستحکم است. اگر آن را
حذف کنید، اسکریپت آن را از پنل روی HTTPS می‌گیرد — اعتماد در نخستین استفاده،
که یک رکورد DNS ربوده‌شده می‌تواند آن را خنثی کند.

> **پیش از آنکه تک‌خطی کار کند، باید باینری‌های عامل را منتشر کنید.** به
> [دانلود باینری‌ها](#دانلود-باینریها) نگاه کنید.

### نصب دستی

```bash
sudo install -m 0755 antimage-node /usr/local/bin/antimage-node
sudo mkdir -p /etc/antimage /var/lib/antimage && sudo chmod 700 /var/lib/antimage
sudo tee /etc/antimage/node.yaml >/dev/null <<'YAML'
panel_url: https://panel.example.com:8443
token: YOUR_ENROLMENT_TOKEN
ca_fingerprint: THE_PANEL_CA_FINGERPRINT
state_dir: /var/lib/antimage
YAML
sudo chmod 600 /etc/antimage/node.yaml
sudo cp packaging/antimage-node.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now antimage-node
```

### بوت‌استرپ SSH از پنل

`POST /api/v1/nodes/{nodeID}/bootstrap-ssh` نصب‌کننده را روی SSH در دو فاز اجرا
می‌کند: فراخوانی نخست اثر انگشت کلید میزبان را برمی‌گرداند تا یک انسان آن را
تأیید کند، و فراخوانی دوم فقط در برابر همان کلید پین‌شده اجرا می‌شود.
**اعتبارنامه‌های SSH هرگز ماندگار نمی‌شوند** — نه جدولی، نه ستونی، نه
سریال‌سازی‌ای — و مادهٔ کلید پیش از بازگشت درخواست از حافظه پاک می‌شود.

## پیکربندی

### فلگ‌های `antimage-panel`

| فلگ | نوع | پیش‌فرض | الزامی | هدف |
|---|---|---|---|---|
| `--data-dir` | مسیر | `/var/lib/antimage` | خیر | پایگاه‌داده، کلید اصلی، فایل‌های دانلود. باید مود 0700 داشته باشد. |
| `--http` | نشانی گوش‌دادن | `:8080` | خیر | API اپراتور و رابط کاربری. یک پایان‌دهندهٔ TLS جلوی آن بگذارید. |
| `--grpc` | نشانی گوش‌دادن | `:8443` | خیر | لایهٔ کنترل عامل‌ها. مستقیماً mTLS عرضه می‌کند. |
| `--grpc-hosts` | CSV | `localhost,127.0.0.1` | **عملاً بله** | نام‌های DNS و IPهایی که عامل‌ها به آن‌ها وصل می‌شوند؛ به SANهای گواهی تبدیل می‌شود. مقدار پیش‌فرض فقط برای تست محلی کار می‌کند. |
| `--version` | فلگ | — | خیر | چاپ نسخه و خروج. |

### فلگ‌های `antimage-node`

| فلگ | نوع | پیش‌فرض | هدف |
|---|---|---|---|
| `--config` | مسیر | `/etc/antimage/node.yaml` | پیکربندی عامل. |
| `--version` | فلگ | — | چاپ نسخه و خروج. |

### `/etc/antimage/node.yaml`

به [`packaging/node.yaml.example`](packaging/node.yaml.example) نگاه کنید.

| کلید | نوع | الزامی | پیش‌فرض | هدف | نکتهٔ امنیتی |
|---|---|---|---|---|---|
| `panel_url` | رشته | **بله** | — | اندپوینت gRPC پنل، `https://host:port` یا `host:port`. | اگر مسیر، کوئری یا اسکیمی غیر از https داشته باشد، هنگام راه‌اندازی رد می‌شود. |
| `token` | رشته | فقط در اجرای نخست | — | توکن ثبت‌نام یک‌بارمصرف. | به‌محض مصرف از فایل پاک می‌شود. فایل را روی 0600 نگه دارید. |
| `ca_fingerprint` | رشته | **بله** | — | SHA-256 گواهی CA پنل، به‌صورت هگز. | راه‌اندازی از پیکربندی بدون آن **سر باز می‌زند** و به مخزن اعتماد سیستم عقب‌نشینی نمی‌کند. |
| `state_dir` | مسیر | خیر | `/var/lib/antimage` | کلید گره، گواهی، وضعیت تحت مدیریت. | با مود 0700 ساخته می‌شود؛ کلید و گواهی 0600. |
| `node_id` | int | خیر | — | پس از ثبت‌نام نوشته می‌شود. | با دست تنظیمش نکنید. |

### متغیرهای محیطی

| متغیر | مصرف‌کننده | هدف | نکتهٔ امنیتی |
|---|---|---|---|
| `ANTIMAGE_MASTER_KEY` | پنل | کلید اصلی ۳۲ بایتی به‌صورت Base64، به‌جای فایل کلید. | رازهای TOTP و کلید خصوصی CA را رمز می‌کند. پایگاه‌دادهٔ درزکرده بدون این کلید هیچ‌کدام را نمی‌دهد. فایل 0600 روی دیسک را ترجیح دهید، مگر آنکه بستر شما رازها را از راه محیط تزریق کند. |
| `ANTIMAGE_DEV_PROXY` | پنل | پروکسی‌کردن درخواست‌های رابط کاربری به یک سرور توسعهٔ Vite. | **فقط برای توسعه.** هرگز در محیط عملیاتی تنظیمش نکنید. |

## پورت‌ها

| پورت | مؤلفه | پروتکل | مواجهه |
|---|---|---|---|
| 8080 | پنل | HTTP | اپراتورها. TLS را جلوی آن پایان دهید. |
| 8443 | پنل | gRPC روی mTLS | گره‌ها. باید از هر گرهٔ تحت مدیریت در دسترس باشد. |
| — | گره | ندارد | عامل خودش به بیرون وصل می‌شود. **هیچ پورت ورودی.** |

## TLS و mTLS

لایهٔ کنترل به‌صورت سرتاسری احراز هویت دوطرفه دارد.

### مدل اعتماد

پنل **CA خصوصی خودش** را اجرا می‌کند که در نخستین راه‌اندازی ساخته و
رمزشده زیر کلید اصلی ذخیره می‌شود. این یک CA از PKI عمومی وب نیست و فقط این‌ها
را صادر می‌کند:

- یک **گواهی سرور** برای شنوندهٔ gRPC پنل، با SANهای گرفته‌شده از
  `--grpc-hosts`، معتبر برای ۹۰ روز، که در هر راه‌اندازی پنل دوباره صادر می‌شود؛
- یک **گواهی کلاینت به ازای هر گره**، `CN = <node id>`، معتبر برای یک سال.

### محل گواهی‌ها

| چه چیزی | کجا | دسترسی |
|---|---|---|
| کلید اصلی | `<data-dir>/master.key` (یا `ANTIMAGE_MASTER_KEY`) | 0600 |
| گواهی CA + کلید مهرشده | جدول `panel_ca` در `<data-dir>/antimage.db` | — |
| گواهی سرور پنل | در حافظه، در هر راه‌اندازی دوباره صادر می‌شود | — |
| کلید خصوصی گره | `<state-dir>/node.key` | 0600 |
| گواهی گره | `<state-dir>/node.crt` | 0600 |
| CA پین‌شدهٔ پنل | `<state-dir>/panel-ca.crt` | 0600 |

### ثبت‌نام چگونه کار می‌کند

1. عامل جفت‌کلید خود را به‌صورت محلی تولید می‌کند. **کلید خصوصی هرگز گره را ترک
   نمی‌کند و پنل هرگز آن را نمی‌بیند.**
2. به پنل وصل می‌شود و راستی‌آزمایی می‌کند که زنجیرهٔ ارائه‌شده گواهی‌ای دارد که
   SHA-256 آن با `ca_fingerprint` می‌خواند. یک رکورد DNS ربوده‌شده چیزی به دست
   نمی‌دهد.
3. توکن یک‌بارمصرف و یک CSR می‌فرستد.
4. پنل راستی‌آزمایی می‌کند که توکن مصرف‌نشده، منقضی‌نشده و به همان گره مقید است،
   یک گواهی کلاینت امضا می‌کند، اثر انگشتش را ثبت می‌کند و توکن را می‌سوزاند.
5. همه چیز پس از آن روی mTLS انجام می‌شود.

پنل به‌جای گواهی برگ به‌تنهایی، `[leaf, CA]` را ارائه می‌کند، دقیقاً به این
دلیل که عاملِ در حال ثبت‌نام — که هنوز هیچ فایل CA ندارد — بتواند اثر انگشت
پین‌شدهٔ خود را در زنجیره پیدا کند.

### اعتبارسنجی و ابطال

شنونده از `VerifyClientCertIfGiven` استفاده می‌کند، **نه**
`RequireAndVerifyClientCert`: ثبت‌نام ناگزیر پیش از آنکه گره هیچ گواهی‌ای داشته
باشد رخ می‌دهد. سرویس کنترل این الزام را به ازای هر RPC اعمال می‌کند و افزون بر
آن، اثر انگشت ارائه‌شده را با `nodes.cert_fingerprint` می‌سنجد.

**ابطال یک فهرست مجاز است، نه CRL.** پنل تنها راستی‌آزماست، پس حذف یک گره اثر
انگشتش را برمی‌دارد و در اتصال بعدی بیرون قفلش می‌کند. نه CRL‌ای برای توزیع هست
و نه پاسخ‌دهندهٔ OCSP‌ای که باید اجرا شود.

### انقضا و چرخش

| گواهی | طول عمر | چرخش |
|---|---|---|
| CA | ۱۰ سال | دستی. جایگزینی‌اش کل ناوگان را دوباره ثبت‌نام می‌کند. |
| سرور پنل | ۹۰ روز | خودکار — در هر راه‌اندازی پنل دوباره صادر می‌شود. پنل را دست‌کم هر ۹۰ روز یک‌بار راه‌اندازی مجدد کنید. |
| کلاینت گره | ۱ سال | **هنوز خودکار نیست — به [محدودیت‌های شناخته‌شده](#محدودیتهای-شناختهشده) نگاه کنید.** |

### دستورهای راستی‌آزمایی

گرفتن اثر انگشتی که اپراتورها باید پین کنند:

```bash
curl -fsS https://panel.example.com/api/v1/ca-fingerprint
```

بررسی آنچه شنوندهٔ gRPC ارائه می‌کند:

```bash
openssl s_client -connect panel.example.com:8443 -showcerts </dev/null 2>/dev/null | openssl x509 -noout -text
```

تأیید گواهی خودِ یک گره:

```bash
sudo openssl x509 -in /var/lib/antimage/node.crt -noout -subject -dates
```

## احراز هویت

- گذرواژه‌ها با **argon2id** هش می‌شوند (m=64 MB, t=3, p=4).
- نشست‌ها **توکن‌های مبهم سمت سرور** هستند، نه JWT، بنابراین ابطال بی‌درنگ اثر
  می‌کند. فقط SHA-256 توکن ذخیره می‌شود.
- کوکی‌ها `HttpOnly`، `Secure` و `SameSite=Strict` هستند.
- **مهلت بی‌کاری ۴ ساعت؛ طول عمر مطلق ۷ روز.** فعالیت، پنجرهٔ بی‌کاری را تمدید
  می‌کند؛ هیچ چیز مهلت مطلق را تمدید نمی‌کند.
- ناکامی‌های ورود به ازای هر حساب و هر IP از نظر نرخ محدود می‌شوند و پس از ۵
  ناکامی حساب قفل می‌شود. یک نام کاربری ناشناخته همان‌قدر زمان می‌برد که یک نام
  شناخته‌شده، پس زمان‌بندی پاسخ فاش نمی‌کند که حسابی وجود دارد یا نه.
- **TOTP** برای هر ادمین اختیاری است. پس از ثبت‌نام، کد معتبر الزامی است و هر
  شاخه‌ای که پنل نتواند راستی‌آزمایی کند **رد می‌کند**، به‌جای آنکه تنها با
  گذرواژه اجازهٔ ورود بدهد.
- ده **کد بازیابی یک‌بارمصرف** هنگام تأیید صادر و یک بار نمایش داده می‌شوند.

ثبت‌نام عامل دوم:

```bash
# returns {"secret":"…","provisioning_uri":"otpauth://…"}
curl -X POST https://panel.example.com/api/v1/auth/totp/enrol -b cookies.txt
# confirm with a code from your authenticator; returns the recovery codes once
curl -X POST https://panel.example.com/api/v1/auth/totp/confirm -b cookies.txt \
  -d '{"totp":"123456"}'
```

## کنترل دسترسی

چهار نقش داخلی:

| نقش | خواندن گره | نوشتن گره | ثبت‌نام | نوشتن سرویس | خواندن ممیزی | نشست‌ها |
|---|---|---|---|---|---|---|
| `super_admin` | ✅ همه | ✅ | ✅ | ✅ | ✅ | ✅ |
| `admin` | ✅ دامنه‌بندی‌شده | ✅ | ✅ | ✅ | ✅ | خودش |
| `reseller` | ✅ دامنه‌بندی‌شده | — | — | ✅ | — | خودش |
| `readonly` | ✅ دامنه‌بندی‌شده | — | — | — | — | خودش |

کنترل دسترسی دو بار و مستقل از هم اعمال می‌شود:

1. **دروازهٔ مجوز** — هر هندلر پیش از انجام کار `rbac.Check` را صدا می‌زند.
2. **محمول دامنه در SQL** — هر پرس‌وجوی دامنه‌بندی‌شده بر پایهٔ فهرست مجاز
   فراخوان فیلتر می‌کند، پس هندلری که بررسی‌اش را فراموش کرده باز هم نمی‌تواند
   گره‌های ادمین دیگری را بخواند.

ردها همراه با مجوز درخواست‌شده، متد و مسیر در لاگ ممیزی نوشته می‌شوند.

## دانلود باینری‌ها

`install.sh` عامل را از پنل می‌گیرد. باینری‌ها را با قراردادنشان در
`<data-dir>/downloads` منتشر کنید:

```bash
sudo mkdir -p /var/lib/antimage/downloads
sudo cp antimage-node-linux-amd64 /var/lib/antimage/downloads/
sha256sum antimage-node-linux-amd64 | awk '{print $1}' \
  | sudo tee /var/lib/antimage/downloads/antimage-node-linux-amd64.sha256
sudo chown -R antimage:antimage /var/lib/antimage/downloads
```

فقط همین چهار نام عرضه می‌شوند، و این سیاهه یک **فهرست مجاز است، نه یک
پاک‌ساز**:

- `antimage-node-linux-amd64` و `.sha256`
- `antimage-node-linux-arm64` و `.sha256`

هر چیز دیگری 404 برمی‌گرداند، از جمله فایل‌هایی که واقعاً داخل آن پوشه هستند.
این اندپوینت بنا بر طراحی احراز هویت ندارد — باینری راز نیست، و آنچه اجازهٔ
پیوستن می‌دهد توکن ثبت‌نام است.

## مدل امنیتی

| ویژگی | چگونه |
|---|---|
| کلیدهای گره | روی خود گره تولید می‌شوند؛ پنل هرگز کلید خصوصی را نمی‌بیند. |
| جعل هویت پنل | عامل‌ها اثر انگشت CA را پین می‌کنند؛ یک رکورد DNS ربوده‌شده چیزی به دست نمی‌دهد. |
| ابطال | فهرست مجاز روی `cert_fingerprint`؛ حذف یک گره بی‌درنگ آن را بیرون قفل می‌کند. |
| رازها در حالت ذخیره | رازهای TOTP و کلید CA با AES-256-GCM زیر یک کلید اصلی مهر می‌شوند که **بیرون** از پایگاه‌داده نگه‌داری می‌شود. |
| اعتبارنامه‌های SSH | هرگز ماندگار نمی‌شوند. نه جدولی، نه ستونی، نه تگ سریال‌سازی؛ پس از استفاده از حافظه پاک می‌شوند. |
| توکن‌های ثبت‌نام | یک‌بارمصرف، انقضای ۳۰ دقیقه‌ای، ذخیره‌شده به‌صورت هش، سوخته پس از مصرف، حذف‌شده از رکوردهای ممیزی. |
| پیمایش مسیر | دانلودها هم از فهرست مجاز استفاده می‌کنند **و هم** از `os.OpenInRoot` که حتی از راه پیوندهای نمادین هم حاضر نیست از پوشه بیرون برود. |
| یکپارچگی ممیزی | فقط-افزودنی؛ `audit_log` هیچ کلید خارجی به `nodes` ندارد، پس حذف یک گره نمی‌تواند ردّ خودش را پاک کند. |
| انحراف | فایل‌های تحت مدیریت چک‌سام می‌شوند؛ ویرایش دستی تشخیص داده و اصلاح می‌شود، نه اینکه بی‌صدا بازنویسی شود. |

آسیب‌پذیری‌ها را مطابق [SECURITY.md](SECURITY.md) گزارش کنید.

## استفاده از API

همهٔ مسیرهای API زیر `/api/v1` هستند. احراز هویت با کوکی نشستی است که از
`POST /auth/login` می‌آید.

```bash
# sign in
curl -c cookies.txt -X POST https://panel.example.com/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"…","totp":"123456"}'

# create a node, then mint a bootstrap command
curl -b cookies.txt -X POST https://panel.example.com/api/v1/nodes \
  -H 'Content-Type: application/json' \
  -d '{"name":"de-1","address":"203.0.113.10"}'

curl -b cookies.txt -X POST https://panel.example.com/api/v1/nodes/1/enroll-token
```

| متد | مسیر | هدف |
|---|---|---|
| POST | `/auth/login` `/auth/logout` | چرخهٔ عمر نشست |
| GET | `/auth/me` | کنشگر جاری و مجوزهایش |
| POST | `/auth/totp/enrol` `/auth/totp/confirm` `/auth/totp/disable` | عامل دوم |
| GET/POST | `/nodes` | فهرست‌کردن و ساختن گره‌ها |
| GET/DELETE | `/nodes/{id}` | جزئیات گره؛ حذف، گره را بیرون قفل می‌کند |
| POST | `/nodes/{id}/enroll-token` | صدور توکن یک‌بارمصرف و دستور بوت‌استرپ |
| POST | `/nodes/{id}/bootstrap-ssh` | بوت‌استرپ SSH دوفازی |
| GET | `/nodes/{id}/revisions` `/nodes/{id}/apply-runs` | تاریخچه و نتایج اعمال گام‌به‌گام |
| POST | `/nodes/{id}/services` | ساختن یک سرویس (بازنگری را بالا می‌برد) |
| PUT/DELETE | `/services/{id}` | به‌روزرسانی یا حذف یک سرویس |
| GET | `/audit` `/sessions` | ردّ ممیزی؛ نشست‌های خود شما |
| DELETE | `/sessions/{id}` | ابطال یکی از نشست‌های خودتان |
| GET | `/events` | وضعیت زندهٔ گره‌ها (SSE) |
| GET | `/ca-fingerprint` | لنگر اعتماد عمومی (بدون احراز هویت) |

خطاها از یک پاکت واحد استفاده می‌کنند: `{"error":{"code":"…","message":"…"}}`.
هر پاسخ `X-Request-ID` را حمل می‌کند که در لاگ ممیزی هم ظاهر می‌شود.

## ثبت لاگ

لاگ‌های ساخت‌یافته روی stderr از راه `log/slog` در Go. زیر systemd:

```bash
sudo journalctl -u antimage-panel -f
sudo journalctl -u antimage-node -f
```

رویدادهای عملیاتی به‌جای stdout به **لاگ ممیزی** می‌روند و از راه
`GET /api/v1/audit` قابل پرس‌وجو هستند. رازها هرگز لاگ نمی‌شوند: توکن‌های
ثبت‌نام از خروجی بوت‌استرپ حذف می‌شوند، و رازهای TOTP و کدهای بازیابی هرگز وارد
یک رکورد ممیزی نمی‌شوند.

## بررسی سلامت

نمای زنده `GET /api/v1/events` (SSE) است که هر ۳ ثانیه یک عکس فوری از وضعیت
می‌فرستد و **در هر تیک نشست را دوباره اعتبارسنجی می‌کند**، پس خروج از حساب یا
ابطال، جریان را بی‌درنگ پایان می‌دهد.

مقادیر وضعیت گره:

| وضعیت | معنا |
|---|---|
| `pending` | ساخته شده، هرگز تماسی نبوده |
| `enrolling` | توکن صادر شده، هنوز ثبت‌نام نشده |
| `online` | جریان برقرار است و heartbeat می‌فرستد |
| `degraded` | متصل است، آخرین اعمال ناموفق یا ناقص بوده |
| `integrity` | **گره سندی را اعمال کرده که پنل هش آن را صادر نکرده بود.** بررسی کنید. |
| `offline` | سه بازه (۹۰ ثانیه) بدون heartbeat |
| `disabled` | به‌صورت اداری غیرفعال شده |

## عیب‌یابی

**پس از جابه‌جایی پنل، دست‌دهی همهٔ گره‌ها ناموفق می‌شود.**
`--grpc-hosts` دیگر با آنچه عامل‌ها به آن وصل می‌شوند نمی‌خواند. خط لاگ
راه‌اندازی (`grpc_cert_hosts=[…]`) را بررسی کنید، فلگ را درست کنید، دوباره
راه‌اندازی کنید. پنل در هر راه‌اندازی گواهی‌اش را دوباره صادر می‌کند.

**`bad interpreter: /bin/bash^M` هنگام اجرای install.sh.**
اسکریپت با پایان‌خط CRLF چک‌اوت شده است. مخزن `*.sh` را از راه `.gitattributes`
به LF مقید می‌کند؛ دوباره کلون کنید یا `dos2unix` را اجرا کنید.

**ادمینی که TOTP را ثبت‌نام کرده نمی‌تواند وارد شود و لاگ می‌گوید box گم شده
است.**
پنل بدون کلید اصلی‌اش راه‌اندازی شده در حالی که رازهای رمزشده وجود دارند. این
رفتار عمدیِ fail-closed است — `master.key` یا `ANTIMAGE_MASTER_KEY` را بازیابی
کنید. کلید را حذف نکنید: رازهای TOTP و کلید CA بدون آن بازیابی‌ناپذیرند.

**یک گره در `integrity` گیر کرده است.**
سندی که اعمال کرده به چیزی هش می‌شود که پنل هرگز صادرش نکرده است.
`GET /api/v1/nodes/{id}/apply-runs` را بررسی کنید. این وضعیت عمداً چسبنده است —
یک heartbeat پاکش نمی‌کند.

**بوت‌استرپ در گام دانلود شکست می‌خورد.**
هیچ باینری‌ای منتشر نشده است. به [دانلود باینری‌ها](#دانلود-باینریها) نگاه کنید.

**`cannot VACUUM from within a transaction` از یک پشتیبان‌گیری.**
در این نسخه رفع شده است. `antimage-ctl` را ارتقا دهید.

## روال ارتقا

```bash
# 1. Back up first — this is consistent and safe while the panel runs.
sudo antimage-ctl --data-dir /var/lib/antimage backup /var/backups/antimage-$(date +%F).db

# 2. Replace the panel binary and restart. Migrations run automatically.
sudo systemctl stop antimage-panel
sudo cp antimage-panel /usr/local/bin/
sudo systemctl start antimage-panel

# 3. Publish the new agent binaries.
sudo cp antimage-node-linux-amd64 /var/lib/antimage/downloads/
sha256sum antimage-node-linux-amd64 | awk '{print $1}' \
  | sudo tee /var/lib/antimage/downloads/antimage-node-linux-amd64.sha256

# 4. Upgrade a node in place — re-running is idempotent and consumes no token.
curl -fsSL https://panel.example.com/install.sh | sudo bash -s -- \
  --panel https://panel.example.com --token '' \
  --ca-fingerprint THE_PANEL_CA_FINGERPRINT
```

مهاجرت‌های پایگاه‌داده فقط رو به جلو هستند و هنگام راه‌اندازی اجرا می‌شوند.
**با بازیابی یک نسخهٔ پشتیبان به عقب برگردید، نه با پایین‌آوردن نسخهٔ باینری.**

## پشتیبان‌گیری و بازیابی

```bash
sudo antimage-ctl --data-dir /var/lib/antimage backup /var/backups/antimage.db
sudo cp /var/lib/antimage/master.key /var/backups/master.key   # 0600, store separately
```

`backup` از `VACUUM INTO` در SQLite استفاده می‌کند و یک کپی سازگار می‌سازد در
حالی که پنل همچنان در حال کار است. حاضر نیست فایل موجود را بازنویسی کند.

> **پایگاه‌داده به‌تنهایی کافی نیست.** بدون `master.key` کلید خصوصی CA و هر راز
> TOTP بازیابی‌ناپذیرند. جداگانه از آن پشتیبان بگیرید — نگه‌داشتنش کنار
> پایگاه‌داده همان دلیلی را که باعث شده بیرون از پایگاه‌داده زندگی کند بی‌اثر
> می‌کند.

بازیابی:

```bash
sudo systemctl stop antimage-panel
sudo cp /var/backups/antimage.db /var/lib/antimage/antimage.db
sudo cp /var/backups/master.key  /var/lib/antimage/master.key
sudo chown antimage:antimage /var/lib/antimage/*
sudo systemctl start antimage-panel
```

## حذف نصب

روی یک گره:

```bash
sudo systemctl disable --now antimage-node
sudo rm -f /etc/systemd/system/antimage-node.service /usr/local/bin/antimage-node
sudo rm -rf /etc/antimage /var/lib/antimage
sudo systemctl daemon-reload
```

گره را در پنل هم حذف کنید — این کار اثر انگشتش را از فهرست مجاز برمی‌دارد.

روی میزبان پنل:

```bash
sudo systemctl disable --now antimage-panel
sudo rm -f /etc/systemd/system/antimage-panel.service /usr/local/bin/antimage-panel
sudo rm -rf /var/lib/antimage      # destroys the database, CA, and master key
sudo userdel antimage
```

می‌کند و هر شش مورد تعریف اتمام کار را پوشش می‌دهد. به Docker نیازی ندارد.

## استقرار

یک پایان‌دهندهٔ TLS جلوی `:8080` بگذارید؛ `:8443` را مستقیم عرضه کنید، چون پنل
خودش آنجا mTLS ارائه می‌کند و یک پایان‌دهنده راستی‌آزمایی گواهی کلاینت را از
کار می‌اندازد.

```
                 ┌── :443  → reverse proxy → :8080   (operators, HTTPS)
  panel host ────┤
                 └── :8443 → antimage-panel          (nodes, mTLS, direct)
```

سیاههٔ بررسی: کاربر `antimage` را بسازید؛ `/var/lib/antimage` روی 0700؛ از
`master.key` جداگانه پشتیبان بگیرید؛ `--grpc-hosts` را روی نام عمومی تنظیم
کنید؛ باینری‌های عامل را منتشر کنید؛ دست‌کم هر ۹۰ روز یک‌بار پنل را دوباره
راه‌اندازی کنید تا گواهی سرور دوباره صادر شود.

## محدودیت‌های شناخته‌شده

این‌ها واقعی‌اند:

- آداپتورهای Xray (VLESS/VMess/Trojan) در زمان اجرا اعمال و راستی‌آزمایی
  می‌شوند؛ WireGuard، Hysteria2، L2TP/IPsec و sing-box پیکربندی می‌سازند اما
  رفتار زمان اجرای همهٔ آن‌ها هنوز راستی‌آزمایی نشده است (ماتریس وضعیت را در
  [README انگلیسی](README.md#protocol-support-matrix) ببینید).
- مدیریت مشترکان، حسابداری ترافیک، سهمیه و لینک اشتراک وجود دارد و کامل است؛
  صفحهٔ اطلاعات اشتراک مرورگر و هدر `Subscription-Userinfo` هم ارائه می‌شود.
- **تمدید خودکار گواهی گره پیاده‌سازی نشده است.** گواهی‌ها یک سال دوام دارند؛
  تمدید در نیمهٔ راه طراحی شده اما ساخته نشده است.
- **رابط کاربری برای ثبت‌نام TOTP وجود ندارد.** اندپوینت‌ها کار می‌کنند؛ SPA
  هنوز صفحه‌ای برایشان ندارد.
- **هیچ تنظیم سراسری «الزام TOTP برای super_admin» وجود ندارد.** عمداً به تعویق
  افتاده است: سیاستی که ورود سوپرادمین‌هایی را که ثبت‌نام نکرده‌اند رد کند
  می‌تواند یک اپراتور را به‌کلی بیرون قفل کند، و نخست به یک راه گریز طراحی‌شده
  نیاز دارد.
- **مقادیر enum که سرور می‌فرستد بدون ترجمه نمایش داده می‌شوند** (`converged`،
  `ok`، `restart`). این‌ها داده‌اند، نه رشته‌های رابط کاربری.
- **کدهای TOTP یک‌بارمصرف نیستند.** یک کد در سراسر پنجرهٔ انحراف ±۳۰ ثانیه‌ای
  معتبر می‌ماند.
- **نمای ممیزی بر پایهٔ دامنه فیلتر نمی‌شود.** دارندهٔ `audit:read` همهٔ ردیف‌ها
  را می‌بیند، از جمله IPهای ورود ادمین‌های دیگر. `reseller` این مجوز را ندارد.
- **هیچ اندپوینت متریکی وجود ندارد** (نه Prometheus و نه چیز دیگری).
- **مهاجرت‌های رو به پایین تست نشده‌اند.** با بازیابی یک نسخهٔ پشتیبان به عقب
  برگردید.
